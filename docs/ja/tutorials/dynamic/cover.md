# カバー関数

すでにご存じのとおり、`uncover` と `#pause` はどちらも `cover` 関数を使って、表示されない内容を隠します。では、ここでいう `cover` 関数とは具体的に何でしょうか？

## 既定のカバー関数：`hide`

`cover` 関数は `self.methods.cover` に格納されるメソッドであり、後で `uncover` と `#pause` から使用されます。

デフォルトの `cover` 関数は [hide](https://typst.app/docs/reference/layout/hide/) 関数です。この関数はレイアウトに影響を与えずに内部の内容を不可視にします。以下で詳しく説明するように、設定に書き込まれています。

## カバー関数を変更する

場合によっては独自の `cover` 関数を使用したいことがあります。その場合、次の方法で独自の `cover` 関数を設定できます。 

```typst
config-methods(cover: utils.hiding-cover)
```

自作のメソッドにTouyingが何を求めているかについては、以下の[独自のカバー関数を作成する](#独自のカバー関数を作成する)を参照してください。

## 透明度や色を変えるカバー関数

Touyingは内容を半透明にするカバー関数をサポートしています。次の設定で有効にできます。

```typst
config-methods(cover: utils.alpha-changing-cover)
```

`alpha: ..` パラメーターによる透明度の調整は、`.with(alpha: 30%)` を追加することで行えます。

あるいは、その類似の関数である `utils.color-changing-cover` を試してみてもよいでしょう。これはすべての色を指定した色に変更します。


:::tip[内部の仕組み]

`utils.alpha-changing-cover` メソッドは、遭遇するすべての色のアルファ値を下げることで動作します。ネストされたスタイルやコンテキストの各階層でTypstのコンテキストにアクセスする必要があるため、処理コストが高くなることがあります。

プロジェクトのコンパイルが遅くなっていることに気付いたら、`utils.color-changing-cover` に切り替えてみてください。

どちらのメソッドも、表示されるすべての色を変更できるわけではありません。画像やタイリングなど、一部の内容には干渉できません。そのため、両方のメソッドは `fallback-hide` を使用します。これは `utils.semi-transparent-cover` を通して灰色の半透明の矩形を内容に重ね、同様の効果を再現しようとするものです。この関数を主たる半透明カバーとして使うことは、修正されない複数のバグがあるため、もはや推奨されません。 

:::

### 塗りつぶした図形のカバー

独自の背景を描画する要素の色は通常、変更すべきではありません。図形とその上のテキストの両方が同じ色に強制され、テキストが読めなくなるためです。画像が灰色の矩形になる様子を想像してみてください。
したがって、`utils.color-changing-cover` は塗りつぶしのある要素を代わりにフォールバックの非表示処理へ渡すことができます。これは `fallback-for-filled: true`（デフォルト）で制御されます。無効にすると、ほかのすべての要素と同じように色が変更され、スライドが均一に灰色になります。

```typst
config-methods(cover: utils.color-changing-cover.with(fallback-for-filled: false))
```

`utils.alpha-changing-cover` にはこのようなパラメーターはありません。アルファ値を下げることで、図形がその内容と一体化して見えなくなることなく、図形を薄く表示できるためです。

## 独自のカバー関数を作成する

カバー関数は名前付き引数として `self` を、位置引数としてカバーする内容を受け取り、カバーされた内容を返します。

```typst
#let my-cover(self: none, body) = block(hide(body))

config-methods(cover: my-cover)
```

### メソッドの動作を宣言する

Touyingは、メソッドがカバー対象の内容を*削除*するのか、*非表示*にするのか、それとも単に*スタイルを変更*するのかを知る必要があります。これは、カバーされた脚注をどのように描画する必要があるかが変わるためです。

- 内容を削除するメソッドは、本物の脚注を一切生成してはいけません。脚注が属する内容がまだ非表示なのに、脚注の項目が区切り線の下に表示されてしまうためです。Touyingは代わりに、同じ幅を確保するプレースホルダーマーカーを描画します。
- スタイルを変更するだけのメソッドは、本物の脚注を生成し、ほかのすべての内容と一緒に薄く表示する必要があります。

そのため、問い合わせを受けたときには `utils.cover-kind-query` に応答してください。

```typst
#let my-cover(self: none, body) = if self == utils.cover-kind-query {
  "hide"
} else {
  block(hide(body))
}
```

メソッドが内容を削除・非表示にする場合は `"hide"`、スタイルを変更する場合は `"recolour"`、内容の上に描画する場合は `"paint"` を返します。

Touyingに同梱されているすべてのメソッドはこれに応答します。応答しないメソッドについては、返す内容から動作が推測されます。この推測では単純な `hide` は認識できますが、`block` や `place` でラップされているものは認識できません。これが、1行追加してでも動作を宣言する価値がある理由です。

### 図のキャプションをカバーする

`"recolour"` と応答した場合、Touyingは `utils.cover-caption-query` を `self` として渡すこともあります。渡された内容をカバーするだけでは、キャプションをカバーできません。キャプションの `Figure 1:` のような補足文字列と番号はレイアウト時に生成され、その内容の一部ではないため、カバーされないままになります。一方、キャプション要素自体をカバーすると、独立した行へと分離するブロックになってしまいます。代わりに、渡された内容を `show figure.caption` ルールで囲んで返してください。

```typst
#let my-cover(self: none, body) = if self == utils.cover-kind-query {
  "recolour"
} else if self == utils.cover-caption-query {
  show figure.caption: set text(fill: gray)
  body
} else {
  text(fill: gray, body)
}
```

非表示や上からの描画を行うメソッドには、この問い合わせは行われません。それらのメソッドでは、ほかの内容と同じようにキャプション全体がカバーされます。

### 脚注マーカーのカスタマイズ

`config-common(footnote-style: ..)`、つまり通常であれば `show footnote: ..` に渡す関数を使用します。Touyingはこの関数を `show footnote: footnote-style` として設定し、上記のプレースホルダーマーカーの描画にも使用するため、本物の脚注とプレースホルダーの見た目が一貫します。独自に記述した `show footnote: it => ..` ルールは、実際に表示された本物の脚注にしか適用されず、プレースホルダーには適用されません。
